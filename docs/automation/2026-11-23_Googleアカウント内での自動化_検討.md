# お客さんのGoogleアカウントの中だけで作る自動化（n8nなし）検討

作成：2026-11-23 仕組み担当（automation）／依頼：リーダー
対象：最初に売る3つ（①1分返信パック ②予約リマインド ③口コミの見守り）
前提：調べただけ。n8nには何も作っていない・変えていない。

---

## 0. 結論（先に）

- **①と③は、お客さんのGoogleアカウントの中だけで「〇 作れる」。** ②は**メールなら〇、LINEでお客さん（来店者）に送るのは△**（n8n版でも同じく△）。
- 使う道具は **Googleスプレッドシート1枚＋その中に入れるプログラム（Google Apps Script、以下「GAS」）**。Googleフォーム・Gmail・Googleカレンダーはお客さんが今使っているものをそのまま使う。
- **お客さんの月額は、ふつうの規模なら0円**（Googleは無料アカウントでも動く。LINE通知はLINE公式アカウントの無料枠＝月200通以内なら0円。AIの下書きを付けると月数十円〜数百円）。**n8nの月額（約4,000円）がいらなくなる**のが一番の利点。
- 渡し方は **「ひな形のスプレッドシートをコピーしてもらう」形でできる**。ただし、**時間で動く設定（トリガー）はコピーされない**ので、コピー後に「初期設定」ボタンを1回押してもらう（または画面共有で一緒に押す）。
- 弱いところは **「止まったことに当社が気づきにくい」「お客さんごとにファイルが分かれていて一括で直せない」** の2つ。月額の見守りでは「週1回の生存確認メールを当社に届ける仕組み」を必ず入れる。
- 規約の面：**お客さんの仕組みはお客さんのGoogleアカウントで動く**ので、「当社のn8nでお客さんの分を動かしてよいか」という問題が起きない。**「作って渡す」方針にいちばん合う。**

## 2. それぞれ作れるか

### 早見表

| 商品 | 判定 | ひとことで |
|---|---|---|
| ① 1分返信パック | **〇** | Googleフォーム（またはお客さんのHPのフォーム）→ 表に記録 → 自動返信メール → 担当者のLINEに通知。すべてGASでできる |
| ①オプション AI返信の下書き | **〇** | GASからClaude（またはGemini）を呼んで、Gmailの「下書き」に入れる。送信は人 |
| ② 予約リマインド（メール） | **〇** | Googleカレンダーか表の予約を毎日1回見て、前日にメール。しばらく来ていない人へのお知らせもメールなら〇 |
| ② 予約リマインド（LINEで来店者へ） | **△** | LINEで送るには来店者を「友だち」にして予約とひもづける仕組みが要る（n8n版でも同じ手間）。GASでも作れるが手間とくせがある |
| ③ 口コミの見守り＋AI下書き | **〇** | Googleから届く「新しいクチコミ」の通知メールをGASが数分おきに探す → LINEに通知 → AIが返信の下書き。Googleへの申請は不要 |

### ① 1分返信パック（〇）

作り方の概要：
1. **受け口は3通りから選ぶ**
   - (a) **Googleフォーム**（HPが無い・作り直したくないお客さん向け。一番簡単）：フォームの送信をきっかけに動く（「フォーム送信時」トリガー）。回答は自動でスプレッドシートに入る。
   - (b) **お客さんのHPのフォーム**：GASを「ウェブアプリ」として公開し、HPのフォームの送り先にする（当社の「HP問い合わせフォーム受付」と同じ考え方。おとり欄・送信までの秒数チェックで迷惑送信よけ）。
   - (c) **問い合わせが「メール」で届いているお客さん**（WordPressのフォームなど）：Gmailを5〜10分おきに探して、新しい問い合わせメールを読む。
2. 表（スプレッドシート）に1行追加（受付日時・名前・連絡先・内容・対応状況）。
3. 問い合わせた人へ**自動返信メール**（お客さんのGmailから送る。「〇営業日以内にご連絡します」などの定型文）。
4. 担当者の**LINEに通知**（LINE公式アカウントのMessaging APIをGASから呼ぶ。3章）。
5. （オプション）AIが返信文の**下書き**を作り、Gmailの下書きフォルダーに入れる＋「下書きできました」とLINE。送信は人。
6. 失敗したら担当者と当社にメール（6章の見守り）。

### ② 予約リマインド（メール〇／LINEは△）

作り方の概要：
- **前日のお知らせ**：毎日1回（例：17〜18時）動くトリガー → Googleカレンダーの「明日の予定」を読む（予定のメモ欄にお客さんのメールアドレスを入れておく決まりにする）か、予約表（スプレッドシート）を読む → 1人ずつメールを送る → 「送った」印を付けて二重送信を防ぐ。
- **しばらく来ていない人へのお知らせ**：顧客表に「最後に来た日」を入れておく → 週1回動いて、〇日以上来ていない・まだ送っていない人にだけメール。**配信停止の方法と送信者名を必ず書く**（特定電子メール法）。1日の送信数の上限（下表）があるので、多い日は翌日に分けて送る作りにする。
- **LINEで来店者に送る場合（△）**：来店者に店のLINE公式アカウントを友だち追加してもらい、その人の「ユーザーID」と予約をひもづける必要がある（例：友だち追加後に予約番号や電話番号を送ってもらい、GASが受け取って表に記録）。GASで受け取る仕組みは作れるが、(1) 来店者の協力が要る、(2) お客さんが既に別のLINEツール（Lステップ等）を使っていると受け取り先がぶつかる、(3) GASをLINEの受け取り先にすると細かいくせがある【要テスト】、の理由で△。**まずメールで売り、LINEは追加オプション**にするのがおすすめ。
- 予約の台帳そのものは**お客さんのカレンダー／予約サービスが正**。当社が台帳を持たない（前回の判定と同じ方針）。

### ③ 口コミの見守り＋AI下書き（〇）

作り方の概要：
1. お客さんのGoogleビジネスプロフィールで、新しいクチコミの**メール通知をオンにしておく**（お客さんの作業。通知先はスクリプトを入れるGmail）。
2. GASが10〜15分おきにGmailを探す（Googleからの「クチコミ」通知メールで、まだ処理していないもの）。
3. メールから星の数・投稿者名・本文を抜き出す（メールの見た目が変わっても崩れにくいように、抜き出しもAIに任せる作りがおすすめ）。
4. AIが返信の下書きを作る（店の名前・口調・言ってはいけないこと、を最初に設定しておく）。星1〜2は「必ず人が直す」の印を付ける。
5. LINEに「新しい口コミ（★の数・本文）＋返信の下書き」を送る。表にも記録。
6. **返信は人がGoogleマップの画面に自分で貼り付ける**（自動では書き込まない。Googleへの申請が不要なのはこの形だから）。
- 歯科・クリニックは医療広告の決まりがあるので下書きまで（前回と同じ）。

### 無料枠の制限（公式の数字）

| 項目 | 無料のGoogleアカウント（gmail.com） | Google Workspace（有料・会社のドメイン） | ①②③への影響 |
|---|---|---|---|
| GASから送れるメールの宛先数 | **1日100人** | **1日1,500人**（同じドメイン内は2,000） | ①は問い合わせ数＋α なので普通は足りる。②の「来ていない人へ一斉」は1日100人まで→分けて送る |
| 1回の実行時間 | **6分** | **6分** | 1回で何百件も処理しない作りにする（普通は数秒で終わる） |
| トリガー（時間で動く等）の合計実行時間 | **1日90分** | **1日6時間** | 10分おきに数秒動く程度なら1日数分。十分 |
| トリガーの数 | 1つのスクリプトにつき**20個** | 同じ | ①②③で使うのは3〜5個 |
| 外部への呼び出し（LINE・AIなど） | **1日20,000回** | **1日100,000回** | 十分 |
| 同時に動ける数 | 1人30（スクリプトあたり1,000） | 同じ | 問題なし |
| 時間で動くトリガーの細かさ | 「1・5・10・15・30分ごと」「毎時」「毎日〇時台」など。**毎日〇時は「〇時〜〇時59分のどこか」**で、分単位の正確さは保証されない | 同じ | リマインドは「前日の夕方」程度で十分。①は「フォーム送信時」なのですぐ動く |

出典：
- GASの割り当て（制限）：https://developers.google.com/apps-script/guides/services/quotas （日本語：https://developers.google.com/apps-script/guides/services/quotas?hl=ja ）
- 時間で動くトリガー：https://developers.google.com/apps-script/reference/script/clock-trigger-builder ／ https://developers.google.com/apps-script/guides/triggers/installable

※Gmailの画面から人が送る上限（無料500通／日、Workspace 2,000通／日）とは別に、**GASから送る分は上の数字が上限**。

## 3. LINEへの通知（Messaging API）

### GASから呼べるか → 呼べる
- GASの「外部を呼ぶ機能（UrlFetchApp）」で、LINEの送信の窓口（`https://api.line.me/v2/bot/message/push`）に、合言葉（チャネルアクセストークン）を付けて送るだけ。**当社のn8nの「HP問い合わせフォーム受付」と同じ呼び方**なので、中身はそのまま移せる。
- 合言葉は**スクリプトの「プロパティ（隠し設定）」に保存**し、表のセルには書かない。

### 通数と料金（LINE公式アカウント・日本）

| プラン | 月額（税別） | 無料で送れる通数 | 上限を超えたら |
|---|---|---|---|
| コミュニケーション（無料） | 0円 | **月200通** | 送れない |
| ライト | 5,000円 | 月5,000通 | 送れない |
| スタンダード | 15,000円 | 月30,000通 | 追加料金で送れる |

- **Push（こちらから送る）は通数に数える。Reply（相手から来たメッセージへの返事）は数えない。**
- 2026年10月に改定があったが、月額と無料通数は据え置きという情報（前回の判定資料より）。
- 出典：https://developers.line.biz/ja/docs/messaging-api/pricing/ ／ https://www.lycbiz.com/jp/manual/OfficialAccountManager/account-settings （前回資料の出典も参照）

**①③の「担当者への通知」は、送り先が担当者1〜数人なので月200通に収まることが多い**（問い合わせ月50件×担当2人＝100通）。②で来店者全員にLINEを送ると200通はすぐ超える → ライト以上が必要。

### お客さん側で必要な準備（画面共有で20〜30分）
1. LINE公式アカウントを作る（無い場合。無料）。
2. LINE公式アカウントの設定で「Messaging API」を使う設定にする（LINE Developersに登録され「チャネル」ができる）。
3. チャネルの画面で**チャネルアクセストークン**を発行し、GASの初期設定画面に貼る。
   - トークンには種類がある（長く使えるもの／最長30日のもの／15分のもの）。**ひな形では「長く使えるトークン」を使う**想定。取り消し・再発行したら貼り直しが必要。どの種類が今発行できるかは**作る前に公式で確認**（https://developers.line.biz/ja/docs/basics/channel-access-token/ ）。
4. 通知を受け取る担当者が、その公式アカウントを**友だち追加**する。
5. 担当者の「ユーザーID」を調べてGASに設定する（店主本人ならチャネルの基本設定に「あなたのユーザーID」が出る。スタッフの分は、友だち追加したときにIDを記録する小さな仕組みを足す）。
6. **お客さんが既にLINEの別ツール（Lステップ等）でMessaging APIを使っている場合は、受け取り先がぶつからないか事前に確認**（①③の通知＝送るだけなら基本ぶつからない）。

## 4. AIの下書き（③、①のオプション）

### 呼び方
- GASからClaude API（`https://api.anthropic.com/v1/messages`）、またはGemini APIを、LINEと同じく外部呼び出しで呼ぶ。APIキーはスクリプトの隠し設定に保存。

### 費用の目安（Claude・公式料金。1ドル＝155円で計算）

| モデル | 料金（100万トークンあたり 入力／出力） | 口コミ1件の下書き（入力約2,000・出力約500トークン） | 月30件 |
|---|---|---|---|
| Claude Haiku 5.5 | $0.10／$0.50 | 約0.07円 | 約2円 |
| Claude Sonnet 5.5 | $2／$10 | 約1.4円 | 約42円 |
| Claude Opus 5.5 | $4／$20 | 約2.8円 | 約84円 |

- ①の問い合わせ返信の下書き（よくある質問・料金表を毎回渡すので入力が多い。入力約5,000・出力約800トークン）：Sonnet 5.5で1件約2.8円、**月100件で約280円**。
- 出典：https://platform.claude.com/docs/en/about-claude/pricing （直接確認。2026-11-23時点）
- **おすすめはSonnet 5.5**（日本語の口コミ返信の質と費用のバランス）。件数が多いお客さんはHaiku 5.5も試す。
- Claude APIは**前払いでクレジットを買う形**（クレジットカード）。最低購入額は申込画面で確認。使いすぎ防止に**月の上限額を設定**してもらう。

### Gemini APIの場合
- Googleのアカウントがあればキーを無料で作れ、**無料枠がある**。ただし公式の料金ページでは「**無料枠の内容はGoogleの製品の改善に使われる**」とされ、有料枠は原則使われない（モデルにより条件が違うので要確認）。→ **お客さんの顧客の名前や問い合わせ内容（個人情報）を送るなら、無料枠は使わない。** 有料にするにはGoogle Cloudで支払い設定が必要で、お客さんにとってはClaudeと手間は大きく変わらない。
- 無料枠の1日の回数はモデルごとに違い、少ないもの（1日20回程度という報告）もある。料金も2027年に値上げ予定の表示があるなど動きが大きい。
- 出典：https://ai.google.dev/gemini-api/docs/pricing ／ https://ai.google.dev/gemini-api/docs/rate-limits

### APIキーを誰の名義にするか → **お客さん名義が基本**
| 名義 | 良い点 | 悪い点 |
|---|---|---|
| **お客さん名義（おすすめ）** | 個人情報の流れが「お客さん→AI会社」で完結し、当社を通らない。費用はお客さんに直接請求。規約上もすっきり | お客さんにAI会社の登録・カード登録をしてもらう手間（画面共有で15分） |
| 当社名義 | お客さんの手間がない。AI代を月額に含められる | **キーがお客さんのスクリプトの中に入る＝お客さん側の人が見られる**（漏れたら当社に請求が来る）。他社の個人情報が当社の契約で処理される（委託の整理が必要）。おすすめしない |

- 「AIの下書き」はオプション扱いにして、**AIなしでも①③は動く作り**にする（キーが無い・残高切れのときは「下書きなし」で通知だけ届く）。

## 5. 当社の作業時間・渡し方・お客さんの操作

### 当社の作業時間の目安【推測】

| | ひな形づくり（1回だけ） | 2社目以降（1社あたり） |
|---|---|---|
| ① 1分返信パック | 8〜12時間（3つの受け口・迷惑送信よけ・テスト込み） | 2〜3時間（文面・項目の調整＋導入の打ち合わせ） |
| ①オプション AI下書き | ＋4〜6時間 | ＋1時間（よくある質問・料金表の整理） |
| ② 予約リマインド（メール） | 8〜12時間 | 2〜4時間（カレンダーの書き方の決め方による） |
| ② LINEで来店者へ | ＋16〜24時間 | ＋3〜4時間 |
| ③ 口コミの見守り＋AI下書き | 6〜10時間（通知メールのサンプル集め込み） | 1.5〜2時間 |
| 共通：初期設定ボタン・見守り（生存確認）・手順書 | 6〜8時間 | — |

※n8n版より**ひな形づくりは少し重い**（部品を組むのではなくプログラムを書くため）が、**2社目以降は同じくらいかやや軽い**（コピーして設定するだけ）。

### 渡し方 → **スプレッドシートのコピーで渡せる**
1. 当社がひな形のスプレッドシート（GAS入り）を作る。
2. お客さんに「コピー用リンク」（共有リンクの末尾を `/copy` にしたもの）を送る。開くと「コピーを作成」ボタンだけの画面になり、押すと**お客さんのGoogleドライブにお客さんのものとして**コピーされる。中のGASも一緒にコピーされる。
   - 公式：「元のファイルをコピーした人は、コピーの持ち主になり、スクリプトのコピーを見て動かせる」（https://developers.google.com/apps-script/guides/bound ）
3. **時間で動く・フォーム送信で動く設定（トリガー）はコピーされない**ので、メニューに「初期設定」ボタンを作っておき、お客さんが1回押すと必要なトリガーが全部作られるようにする。
4. 保守のため、お客さんにコピーしたファイルの**編集者として当社を追加**してもらう（任意。当社が中を直せるように）。

**大事な注意：トリガーは必ずお客さん本人のアカウントで作る。** 当社のアカウントで「初期設定」を押すと、メール送信やGmailの読み取りが**当社の名前で動いてしまう**（お客さんのGmailを読めない・当社のGmailから送ってしまう）。画面共有のときも、押すのはお客さん。

### お客さんがやる操作（画面共有で一緒にやれば30〜45分）
1. コピー用リンクを開いて「コピーを作成」を押す。
2. コピーしたスプレッドシートの上のメニュー「自動化」→「初期設定」を押す。
3. 許可の画面が出る：
   - 自分のGoogleアカウントを選ぶ
   - **無料のGoogleアカウントの場合、「このアプリはGoogleで確認されていません」という画面が出る** → 「詳細」→「（ファイル名）（安全ではないページ）に移動」を押す。自分で入れたスクリプトなので問題ないが、**怖く見えるので事前に「この画面が出ます」と説明する**。Google Workspaceでスクリプトの持ち主と使う人が同じ会社なら、この画面は出ない（https://developers.google.com/apps-script/guides/client-verification ／ https://support.google.com/cloud/answer/7454865 ）。
   - **「すべて選択」にチェックを入れて「続行」**。2025年からGoogleの許可画面は項目ごとにチェックを外せるようになった。**一部を外すとその機能だけ動かない**ので、全部にチェックしてもらう（プログラム側でも「足りない許可があれば初期設定を止めて知らせる」作りにする）。出典：https://workspaceupdates.googleblog.com/2025/01/granular-oauth-consent-in-google-apps-script.html ／ https://developers.google.com/apps-script/concepts/scopes
4. 初期設定の入力画面で、LINEのチャネルアクセストークン、通知先、（AIを使うなら）APIキー、店名・返信の口調などを入れる。
5. テスト送信ボタンを押して、LINEとメールが届くのを確かめる。
6. ③の場合：Googleビジネスプロフィールで、クチコミのメール通知がオンになっていることを確かめる。

## 6. 保守（止まるリスクと月額の見守り）

### 止まる・変わるリスク

| リスク | 起きやすさ | 対策 |
|---|---|---|
| Googleが制限の数字や仕様を変える（公式に「予告なく変わる」と明記） | 中 | 毎月の見守りで公式の変更情報を確認。実例：古い動き方（Rhino）は2026年1月31日で廃止され、移行しないスクリプトは止まった（https://developers.google.com/apps-script/guides/support/sunset ）。ひな形は新しい方式（V8）で作る |
| Googleの「クチコミ通知メール」の見た目が変わり、読み取れなくなる（③） | 中 | 読み取りをAIに任せる・決まった文字に頼りすぎない。週1回の生存確認で「今週の口コミ0件」が続いたら確認 |
| AIのモデルの提供終了（モデル名の書き換えが必要） | 中（年1回程度） | モデル名を設定画面の1か所にまとめる。見守りで終了予定を確認して書き換え |
| LINEのトークンが取り消された・料金プランが変わった | 低〜中 | 送信失敗を当社に知らせる。毎月、通数（月200通に近いか）を確認 |
| お客さんが許可を取り消した・パスワード変更や2段階認証の変更・アカウント停止・担当者の退職でアカウント削除 | 中 | **スクリプトは店のアカウント（個人のスタッフではなく）で動かす**ことを最初に決める。失敗時の通知で気づく |
| 1日の上限を超えた（②の一斉メールなど） | 低 | 送信数を数えて、上限の手前で翌日に回す作り |
| Googleの失敗通知メールがお客さんにしか届かず、気づかれない | **高** | 下の「生存確認」で当社が気づけるようにする |

### 月額の見守りでやること（案）
1. **生存確認（自動）**：各お客さんのスクリプトが**週1回、当社の見守り用アドレスに「動いています（今週の件数）」メールを送る**。失敗したときは**その場で当社とお客さんにメール**（エラーをつかまえて送る作り）。
   - 当社側は、届いたメールを既存の「ランサーズ通知→LINE」と同じ作りで読んで、**来なかったお客さんだけ当社のLINEに知らせる**こともできる（当社自身の業務の見張りなので、お客さんの仕組みを当社のn8nで動かすことにはあたらない、と考えられる。ただし気になるならメールを目で見るだけでもよい）。
2. **月1回の点検（1社15〜30分）**：生存確認の記録、LINEの通数、AIの使用額、エラーの有無を見て、短い報告をLINEで送る。
3. **変更への対応**：Google・LINE・AI会社の仕様変更やモデル終了のときに、スクリプトを直す（当社が編集者になっていれば当社で直せる。**お客さんごとにファイルが分かれているので、1社ずつ直す必要がある**）。
4. **文面の変更**：自動返信の文・リマインドの文・AIに渡す「よくある質問」の更新を、LINEで依頼を受けて直す（月1〜2回まで、など範囲を決める）。
5. **使い方の質問対応**。

※値段はオーナーの決定。お客さんはn8nの月額（約4,000円）がいらなくなるので、**その分を見守り料に回しても、お客さんの総額はn8n版より安くなる**。

## 7. n8n版との比較

| 項目 | Googleアカウント内（GAS）版 | n8n版（お客さんのn8nに入れて渡す） | n8n版（当社のn8nで代わりに動かす） |
|---|---|---|---|
| お客さんの月額 | **0円**（AI・LINE有料プランを使う分だけ） | n8nの月額 約4,000円〜＋α | 当社の月額に含める |
| 規約の問題 | **なし**（お客さんのアカウントで動く） | なし | **未確認（販売停止中）** |
| 個人情報の置き場所 | **お客さんのGoogleの中だけ** | お客さんのn8n | 当社のn8n（委託の契約が必要） |
| お客さんの分かりやすさ | **見慣れたスプレッドシート**。記録も表で見られる | n8nの画面は分かりにくい | お客さんは何も触らない |
| 導入時のお客さんの手間 | コピー＋初期設定＋許可画面（怖い表示が出る） | n8nの登録・カード登録・設定 | ほぼなし |
| 当社のひな形づくり | プログラムを書くので**やや重い** | 部品を組むので軽い。当社に実績あり | 同左 |
| 2社目以降の手間 | コピーして設定（軽い） | 書き出して読み込み＋設定 | 当社の中で複製（軽い） |
| 止まったことに気づく | **気づきにくい**（生存確認メールを作り込む必要） | お客さんのn8n次第（当社は見えない） | **気づきやすい**（当社のエラー通知に集約） |
| 一斉に直す | **できない（1社ずつ）** | できない（1社ずつ） | できる |
| 処理の重さ・制限 | 1回6分、メール1日100人（無料アカウント）など。小さなお店なら十分 | n8nのプランの実行回数 | 当社のプランの実行回数を全社で分け合う |
| すぐ反応できるか | フォーム送信は即時。メール・口コミは5〜15分おきに確認 | Webhookは即時。メールは数分おき | 同左 |
| できることの広さ | Google・LINE・AIが中心。Instagram投稿など他社サービスは作れるが手間が増える | 部品が多く、広い | 同左 |
| 当社が離れた後も動くか | **動く**（お客さんのもの） | 動く（n8nの契約が続けば） | 止まる |

**まとめ**：①②（メール）③は**GAS版を基本**にし、Instagram自動投稿のような他社サービスが多く絡むものや、たくさんのお客さんを一括で見たいものはn8n版、という分け方がおすすめ。
