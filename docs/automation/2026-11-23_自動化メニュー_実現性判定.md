# 「業務の自動化の代行」メニュー 実現性判定（技術面）

作成：2026-11-23 仕組み担当（automation）／依頼：リーダー
対象：当社のn8n（https://turtlead.app.n8n.cloud）で、お客さん（地域の中小企業）の仕組みを作って代わりに動かす商品（案：最初20万円＋月1万円・税抜）
範囲：**技術的に作れるか**だけ。業種ごとのニーズは営業担当の資料を見る。
※n8nは**読み取りだけ**で調べました（何も作っていない・変更していない）。get_user_preferences は「設定なし」でした。

---

## 0. 結論（先に）

1. **すぐ売れる（当社にほぼ同じ仕組みがある）**：
   - 問い合わせフォーム → 表に保存 → LINE／メール通知（＋定型の自動返信メール）
   - 問い合わせメールをAIが読んで「返信の下書き」を作り、LINEで知らせる（送信は人）
   - Instagramの自動投稿（予定表から）※Metaの預かり方は営業資料11-3の決定待ち
   - 予約・申込の前日リマインド（メール）
   - 名刺・書類の写真をAIが読んでスプレッドシートに入れる
   - Googleの新しい口コミを（Googleからの通知メール経由で）LINEに知らせる＋返信文の下書き
2. **少し準備すれば売れる**：LINE公式アカウントの自動応答・リマインド、Googleビジネスプロフィール（口コミ返信の自動書き込み・投稿）、Facebook・X・YouTubeへの投稿、毎月のレポート、求人応募の一次対応、見積もり・請求書の下書き、留守電の文字起こし、売上・在庫の集計通知
3. **やめたほうがよい（今は売らない）**：TikTokの自動投稿（審査前は「自分だけに表示」でしか投稿できない）、AIが内容を読んで**そのまま**お客さんに返信する仕組み、AIが応募者の合否を決める仕組み、SMSを大量に送る仕組み、当社で予約の「台帳」そのものを持つ仕組み
4. **最大の注意点は技術ではなく規約**：n8nクラウドで「他社の仕組みを当社が動かしてよいか」は公式にははっきりしていない（営業資料11-1と同じ結論）。**n8nに書面で確認するまで販売開始しない**。
5. **何社まで動かせるか**：今のプランを仮にPro（月10,000回）とすると、空きは月約3,600回（一時用ワークフローを止めれば約5,000回）。お客さん1社あたり月100〜500回の作りにすれば**約10〜30社**。LINEのAI自動応答のように「1通ごとに1回」動くものを入れると減る。**プランと使用量はオーナーが画面で確認が必要（下の6章）**。

## 1. 調べ方

- n8nの部品（ノード）：search_nodes で一つずつ実在を確認（下の表の「使うもの」はすべて確認済みの名前）。
- 当社の既存の仕組み：search_workflows（73本）、get_workflow_details（「HP問い合わせフォーム受付」）、search_data_tables（9表）、list_credentials（10件）。
- 外部サービスの料金・制限：WebSearch で公式ページ（とその要約）を確認。※この作業環境からは n8n.io・developers.google.com・lycbiz.com を直接開けなかったため、**検索結果に出た公式ページの内容**で確認した。数字は申込み前に公式で再確認が必要。

### 確かめて分かった大事なこと

| 分かったこと | 意味 |
|---|---|
| n8nの「Line」ノードは **LINE Notify 用**（通知を送るだけ）。LINE Notifyは**2025年3月31日に終了**している | LINEは、**今の当社と同じく「HTTP Request」ノードで Messaging API を直接呼ぶ**形で作る（当社の「HP問い合わせフォーム受付」がこの形で、実績あり） |
| n8nに **Google Business Profile ノードがある**（口コミの一覧取得・返信、投稿の作成） | ただしGoogle側の**API利用の申請・承認が必要**（プロフィールが確認済みで60日以上など） |
| n8nに **X（旧Twitter）・YouTube・LinkedIn・Facebook Graph API** のノードがある | X・YouTubeは**API側の料金・審査**が壁 |
| **TikTokのノードは無い** | HTTP Requestで作ることはできるが、TikTok側の審査が壁（3章） |
| Google Gemini ノードに「音声の文字起こし（transcribe）」、OpenAIノードに Whisper の文字起こしがある | 留守電の文字起こしはn8nだけでできる |
| AIの部品：Anthropic（Claude）・Gemini・OpenAI・情報抜き出し（Information Extractor）・分類（Text Classifier） | 「読んで下書き」「名刺を読む」「仕分け」はすべて部品がある。当社には Anthropic の資格情報が既にある |
| freee・Misoca など日本の会計ソフトのノードは無い | freee請求書はAPIがあり、HTTP Requestで作れる（n8n公式のひな形に例あり）。会計ソフトはお客さんによって違うので個別対応 |
| Twilio（SMS・電話）、Gmail、Outlook、Googleスプレッドシート・カレンダー・ドライブ、Google Analytics、Shopify、WordPress、Calendly のノードがある | 主なものはそろっている |

## 5. 当社n8nで動かすときの共通の注意（技術）

1. **お客さんごとに分ける**：ワークフロー名の先頭にお客さん名（例：「【A社】問い合わせ受付」）、資格情報（ログイン情報）もお客さんごとに別にする。n8nの「プロジェクト」で分けられるかは**プランによる【要確認】**。
2. **個人情報を実行記録に残さない**：お客さん用は「成功した実行は保存しない」設定にする（当社の「鹿児島向けページの来訪…」と同じ設定）。
3. **止まったらすぐ分かる**：失敗したら当社のLINEに知らせる共通の仕組み（エラー用ワークフロー）を1本作り、全部のお客さんの仕組みにつなぐ。
4. **送る前に人が見る**：お金・お客さんへの返信・公開投稿は「下書き → 承認 → 送信」。当社のInstagramの「承認済みだけ投稿」と同じ考え方。
5. **毎月の保守の中身**：トークン（通行証）の期限確認（Instagramは60日）、外部サービスの仕様変更への対応、エラーの確認。**1社あたり月15分〜1時間**が目安【推測】。
6. **AI代**：当社の Anthropic の資格情報で払う形なら、使う量は「1件数円」程度の見込み【推測：短い文章の読み書きの場合】。LINEのAI応答のように回数が多いものは上限を決める。

### お客さん1社あたりの回数の見込み
| 組み合わせ | 1社の月の回数 |
|---|---|
| 問い合わせ受付＋自動返信＋LINE通知（A-6＋A-1a） | 10〜100回 |

→ **ふつうの組み合わせで1社 月100〜500回**。

### 何社まで（Pro＝月10,000回と仮定）
| 状態 | 空き | 1社100回なら | 1社300回なら | 1社500回なら |
|---|---|---|---|---|
| 今のまま（月約6,400回） | 約3,600回 | 約36社 | 約12社 | 約7社 |
| 一時用ワークフローを止めた後（月約5,000回） | 約5,000回 | 約50社 | 約16社 | 約10社 |

工夫で増やせる：
- 予定表の確認・リマインドなど「時間で動く」ものは、**全社分を1本のワークフローでまとめて回す**と、社数が増えても回数がほぼ増えない（ただし1社の不具合が他社に響かない作りが必要）。
- 当社の30分ごとの仕組みを1日数回にすれば、さらに枠が空く。
- 回数以外の上限：同時に動ける数（Starterは5件という情報）、メモリ（動画など大きいファイル）。動画を扱うお客さんが増えたら要注意。

**結論：最初の10社前後は回数の面で問題ない見込み。** 20社を超える前にプランの見直し（Proの上の段階）を検討。プラン代はお客さん全体で割る共通費用なので、月1万円×数社で十分まかなえる。
