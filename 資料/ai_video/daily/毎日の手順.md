# AI動画編集部 毎日のショート動画の手順（HyperFrames版の型／YouTube・Instagramリール・TikTok・X）

新しいクラウドのセッションが、ここだけ読めばゼロから1本作れるように書いています。
**作るところまで**です。YouTubeへの公開・投稿、n8n本番の変更はしません（公開はオーナーの承認が必要）。

- 型の元：`資料/ai_video/hyperframes版/`（オーナーが「これはいいね」と選んだ型）
- 作る道具：`資料/ai_video/daily/make_daily.py`（台本.json 1つ → 声 → 場面 → チェック → MP4（場所ごとの3つの版）→ 確認コマ → 場所ごとの文章）
- **場所ごとの版（2026-11-21 オーナー承認）**：毎日の動画を YouTube・Instagramリール・TikTok・X に出す。1回の実行で3つの版と4つの文章ができる（→「4-2. 場所ごとの版」）
- 見本：`資料/ai_video/daily/サンプル/`（台本.json と完成MP4・確認コマ）
- 台本のひな形：`資料/ai_video/daily/台本ひな形/土曜_実例.json`、`土曜_AI社員紹介.json`、`日曜_今週のまとめ.json`
- **土曜は「AI社員紹介」（2026-11-21 オーナー決定）**：仲間のAI社員が1人ずつ登場して、自分の仕事を実例で紹介する回。キャラクターごとに声が変わる（→「2-5. AI社員紹介（staff）」、声の表は `資料/ai_video/AI社員の声.md`）

## 0. 所要時間のめやす

| 作業 | 時間 |
|---|---|
| 最初だけ：Docker起動＋VOICEVOXのイメージ取得（約1.9GB）＋起動 | 3〜6分（イメージがもうあれば30秒） |
| 最初だけ：HyperFrames CLI の取得（npx） | 30秒〜1分 |
| 1本あたり（35秒の動画）：声 15秒・場面 1秒・チェック 10秒・書き出し 約110秒・確認 5秒 | **約2分半**（YouTube版だけのとき） |
| 場所ごとの3つの版（ふつうの日）：本編は1回だけ書き出し、最後の約11秒だけ版ごとに書き出してつなぐ | **＋約3分**（合わせて約5〜6分。最後の部分1つの書き出しは約1分＝Chromeの起動に約30秒かかるため） |

書き出しは「動画の長さ × 約3.2倍」かかります（このクラウドはGPUなし・ソフトウェア描画のため）。

## 1. 準備（セッションの最初に1回）

すべてリポジトリの一番上（`/home/user/turtlead-reels`）で実行します。

### 1-1. テレメトリ（利用状況の送信）を止める ※必ず
```bash
export HYPERFRAMES_NO_TELEMETRY=1 DO_NOT_TRACK=1 DISABLE_TELEMETRY=1
node ~/.claude/skills/hyperframes/scripts/plugin-cli.mjs telemetry disable
```
- `make_daily.py` も中で同じ3つを必ずセットしてから HyperFrames を呼びます。
- HyperFrames スキルの「usage beacon（`hyperframes events`）」と「`feedback`」は**実行しない**。

### 1-2. Docker を起動
```bash
nohup dockerd > /tmp/dockerd.log 2>&1 &
for i in $(seq 1 30); do docker info >/dev/null 2>&1 && break; sleep 1; done
docker info | grep "Server Version"     # 表示されればOK
```

### 1-3. VOICEVOX エンジンを起動（タートルの声＝猫使ビィ）
```bash
docker run -d --rm --name vv -p 50021:50021 voicevox/voicevox_engine:cpu-ubuntu20.04-latest
for i in $(seq 1 60); do curl -s --noproxy '*' -m 2 localhost:50021/version && break; sleep 2; done
```
- `"latest"` などのバージョンが返ればOK。最初はイメージ取得で数分かかります（Docker Hub から取れることは確認済み）。
- 確認：`curl -s --noproxy '*' localhost:50021/speakers | grep -o 猫使ビィ` → 「猫使ビィ」（ノーマル＝id 58）。

### 1-4. HyperFrames（動画にする道具）
- 使い方は `~/.claude/skills/hyperframes/SKILL.md` と `~/.claude/skills/hyperframes-cli/SKILL.md` を先に読む。
- 呼び方：`node ~/.claude/skills/hyperframes/scripts/plugin-cli.mjs <コマンド>`（作業中のプロジェクトのフォルダで）。今回確認したCLIは **0.9.72**。
- スキルが無い環境では、`make_daily.py` が自動で `npx --yes hyperframes@0.9.72` を使います（別の場所なら `HF_CLI=/path/to/plugin-cli.mjs` を指定）。
- Chrome が無いと言われたら：`node ~/.claude/skills/hyperframes/scripts/plugin-cli.mjs browser ensure`
- 必要なもの：Node.js 22以上（`/opt/node22/bin/node`）、ffmpeg / ffprobe、Python3 の numpy と Pillow（無ければ `pip install numpy pillow`）。

### 1-5. フォントの場所

## 2. 台本ファイルを書く

置き場所：`資料/ai_video/daily/<日付>/台本.json`（例：`資料/ai_video/daily/2026-11-21/台本.json`）

**曜日の型**（`type` を書かなければ日付から自動で決まります）

| 曜日 | type | 番組名（画面） | 長さの目安 | items の数 |
|---|---|---|---|---|
| 月〜金 | `weekday` | 今日のAIニュース | 本編30〜45秒＋最後の部分 | 1 |
| 土 | **`staff`**（台本に必ず書く） | AI社員紹介 | 本編30〜50秒＋最後の部分 | 1（→ 2-5） |
| （土・前の型） | `saturday` | AIで仕事が楽になった実例 | 本編30〜45秒＋最後の部分 | 1 |
| 日 | `sunday` | 今週のまとめ | 本編30〜90秒＋最後の部分 | 2〜4（番号①②③が付く） |
| （特別） | `greeting` | チャンネル開設のごあいさつ | 全体45秒以内 | 1（出典URLなしでよい）。見本：`2026-11-21/台本.json` |

※ `type` を書かないと土曜は `saturday`（実例）になります。**土曜は `"type": "staff"` と `"staff": "<主役>"` を書く**（2026-11-21 から）。

### 2-1. 形（見本：`サンプル/台本.json`）
```json
{
  "date": "2026-11-21",
  "type": "weekday",
  "speed": 1.15,
  "hook": {
    "headline": "Claudeに 新しいAIが登場",
    "say": [{"sub": "Claudeに、新しいAIが出ました。", "read": "クロードに、新しいエーアイが出ました。"}]
  },
  "items": [
    {
      "headline": "新しいAI「Claude Fable 5.2」",
      "date_label": "発表 11月9日",
      "source_label": "出典：Anthropic公式",
      "source_url": "https://www.anthropic.com/claude-fable-and-mythos-5-2",
      "beats": [
        {"card": {"type": "title", "text": "新しいAI/**「Claude Fable 5.2」**"},
         "say": [{"sub": "Anthropicが、新しいAI/「Claude Fable 5.2」を出しました。"}]},
        {"card": {"type": "tip", "items": ["ふだんの仕事 → 今のAI", "むずかしい作業 → **新しいAI**"]},
         "say": [{"sub": "ふだんの仕事は、今のAIで十分。"}]}
      ]
    }
  ],
  "highlight": ["Claude Fable 5.2", "十分"],
  "description_extra": "概要欄の1行目に入る説明文"
}
```

### 2-2. 項目の意味
| 項目 | 中身 |
|---|---|
| `date` | 公開する日（YYYY-MM-DD）。画面の「11/21号」「11/21(土)」になる |
| `type` | `weekday` / `saturday` / `sunday` / `staff` / `greeting`（省略で日付から自動。`staff` は書いたときだけ） |
| `staff` | （`staff` の回だけ）主役のAI社員：`design`（デザイン主任）/ `sales`（営業担当）/ `listing`（出品・発信担当）/ `automation`（仕組み担当）/ `research`（調べもの担当） |
| `say[].speaker` | その行を話す人。`leader`（タートル）・`guest`（その回の主役）・`design` など。省略すると **staff の回は本編（items）が主役・それ以外はタートル** |
| `speed` | 声の速さ。省略で **1.15**（猫使ビィは聞き取りやすさ優先で 1.1〜1.2） |
| `voice` | 声を変えたいときだけ。例 `{"name": "猫使ビィ", "style": "ノーマル", "intonation": 1.35, "pitch": 0.0}`（省略でこの標準値）。クレジットは声の名前から自動で「VOICEVOX:名前」になる |
| `hook.headline` | 0秒目から出る見出し（つかみ）。短く、20字以内 |
| `hook.say` | つかみのセリフ。**2秒以内**（1文・15字前後）にする |
| `items[].headline` | 見出しカードの文（上の帯） |
| `items[].date_label` / `source_label` | 見出しカードの下の小さい文字（例「発表 11月9日」「出典：Anthropic公式」） |
| `items[].source_url` | 出典URL。**必須**（概要欄に入る。無いと注意が出る） |
| `items[].source_urls_extra` | 追加の出典URL（あれば。配列） |
| `items[].beats` | カード1枚ずつのまとまり。1ネタで **3〜5枚**（ポイント2〜3つ＋「中小企業ならこう使える」） |
| `beats[].say` | そのカードの間に話すセリフ（字幕1枚＝1要素） |
| `say[].sub` | 字幕。`/` で改行（**2行まで**・1行18字くらいまで）。`**ことば**` で黄色 |
| `say[].speed` | その行だけの話す速さ（省略で全体の `speed`）。例 `{"sub": "…", "speed": 1.0}` |
| `say[].read` | 読み方（省略可）。英語名や数字の読みがあやしいときだけ書く。ひらがな・カタカナで |
| `highlight` | 字幕で黄色にする言葉 |
| `readings` | 読み方の置きかえを追加（例 `{"Sora": "ソラ"}`）。よく使うもの（Claude, ChatGPT, Gemini, AI, 十分, 日本 など）は登録済み |
| `cta_say` | 宣伝カードのセリフを変えたいときだけ（標準：「このキャラクターのようなAI動画を、御社のロゴから作ります。」） |
| `inquiry_say` | YouTube版の問い合わせ案内のセリフを変えたいときだけ（標準：「くわしくは、LINEでお問い合わせください。概要欄のリンクからどうぞ！」）。ほかの版は `inquiry_say_insta_tiktok` / `inquiry_say_x` |
| `sns` | （任意）Instagram・TikTok・X の文章の材料。`headline`（見出し）・`body`（Instagramの本文・2〜4行）・`short`（TikTok・X用の1文・40〜70字）・`tiktok_headline`・`x_headline`・`x_body`・`insta_hashtags`・`tiktok_hashtags`・`x_hashtags`（配列）。書かなければ title と description_extra から自動で作る |
| `〇〇_<場所>` | （任意）本編の言葉をその場所の版だけ変える。例 `"sub_insta_tiktok": "フォローも、/よろしくお願いします。"`、カードは `"text_x"`、見出しカードの小さい文字は `"date_label_x"`、黄色の言葉は `"highlight_insta_tiktok"`、番組名（上の帯・冒頭）は `"program_x"`。場所は `youtube` / `insta_tiktok` / `x`。**使うと本編の書き出しが1回増える**ので、ふだんは本編に「チャンネル登録」「概要欄」「フォロー」など場所の決まった言葉を入れないのが一番 |
| `bye_say` / `bye_text` | しめのあいさつのセリフ／画面の文字を変えたいときだけ（標準は型ごとに自動。下の表） |
| `title` | 決まったタイトル（概要欄の先頭に1つだけ入る）。省略で「見出し｜番組名 日付」の案 |
| `description_extra` | 概要欄の本文（改行は `\n`） |
| `titles` | タイトル案を複数出したいとき（配列） |
| `hashtags` | 概要欄のハッシュタグを変えたいとき |
| `program` | 番組名を変えたいときだけ |

### 2-3. カードの種類（`card.type`）
| type | 使いどころ | 書く項目 |
|---|---|---|
| `title` | 見出し・大きな一言 | `text`（`/`で改行・`**`で黄色）、`chip`（小さい札・任意） |
| `number` | 数字を数え上げて見せる | `top`（上の小さい文）、`prefix`、`value`（数字）、`suffix`、`after`、`note` |
| `points` | ポイント2〜3つ（チェック印つき・セリフに合わせて1つずつ出る） | `items`（最大3）、`title`（任意） |
| `tip` | 「中小企業ならこう使える」の札＋2〜3行 | `items`（`→` は水色になる）、`label`（札の文字を変えるとき） |
| `stamp` | ハンコ（ベータ・無料・最大2.5倍など） | `stamp`、`text` |
| `icon` | アイコン＋文 | `icon`（`pin` / `phone` / `clock`）、`text`、`note` |
| `team` | 仲間（AI社員）の紹介。画像＋名札を3体＋2体で並べる。この間メインのタートルは隠れる | `title`、`members`（`img`＝リポジトリからのパス、`name`、`color`） |

**毎回同じで自動で入るもの**（台本に書かなくてよい）
- 上部の帯「AIが情報収集から動画まで作っています」
- 冒頭と最後の「この動画は、タートルアドのAIチームが情報収集から台本・音声・映像まで作っています」
- クレジット「VOICEVOX:猫使ビィ」（画面下・最後の宣伝カード・概要欄。声を変えると自動で変わる。**AI社員が話す回は、使った声を全部並べる**：「VOICEVOX:猫使ビィ、VOICEVOX:冥鳴ひまり」）
- **最後の部分（毎日すべての動画に自動で入る。2026-11-21 オーナー指示）**：本編 → ①宣伝カード → ②問い合わせ案内 → ③しめのあいさつ の順。合わせて約12〜15秒。
  1. **宣伝カード**（約4秒）：「このキャラクターのようなAI動画を、御社のロゴから作ります」「キャラクターAI動画のご相談はこちら」「LINE公式 @486zunqz」「turtle-ad.com」。タートルは小さくなってカードの下で手をふる。
  2. **問い合わせ案内**（約5.5秒・速さは全体の0.9倍でゆっくり）：声「くわしくは、LINEでお問い合わせください。○○のリンクからどうぞ！」。カードの上半分が「くわしくは LINE でお問い合わせください」「▼ ○○のリンクから ▼」（矢印が動く）に切りかわる。LINE公式・turtle-ad.com はそのまま。**○○と矢印・タートルの動きは場所ごとの版で変わる**（下の表）。

  | 版（ファイル） | 声の最後の一言 | 画面の文字 | タートル |
  |---|---|---|---|
  | YouTube（`_youtube.mp4`） | 概要欄のリンクからどうぞ！ | ▼ 概要欄のリンクから ▼ | 下（概要欄）を指すように何度もうなずく |
  | Instagramリール・TikTok（`_insta_tiktok.mp4`。同じ動画を両方に使う） | プロフィールのリンクからどうぞ！ | ▲ プロフィールのリンクから ▲ | 上げた手で上を指すように、上へ何度もはねる |
  | X（`_x.mp4`） | 投稿のリンクからどうぞ！ | ▲ 投稿のリンクから ▲（Xは投稿の文とリンクが動画の上に出るので上向き） | 上へ何度もはねる |
  3. **しめのあいさつ**（約3〜5秒・速さ0.92倍）：画面に大きく「また明日ね！」など、タートルがもとの大きさに戻り、体をゆらしながら大きく手をふって終わる（手ふりのコマは make_daily.py が上げている手を傾けて自動で作る）。

  | 型 | しめのセリフ | 画面の文字 |
  |---|---|---|
  | weekday・saturday | また明日ね！ | また明日ね！ |
| staff | タートル「また明日ね！」→ 主役「またね！」（主役も右に出ていっしょに手をふる） | また明日ね！ |
  | sunday | また来週もよろしくね！ | また来週も よろしくね！ |
  | greeting | 明日から毎日お届けするので、また見てね！バイバイ！ | また見てね！ |
- **概要欄.txt の形（自動）**：①タイトル → ②「▼ お問い合わせ・ご相談はこちら」（LINE公式・お問い合わせフォーム・ホームページ・キャラクターAI動画/リール・AI活用サポート/AI顧問・ホームページ制作・電話 099-210-3511 受付9:00〜18:00 土日祝休み）→ ③説明文（`description_extra`）→ ④出典（ニュースの回）→ ⑤「この動画は、タートルアドのAIチームが…」→ ⑥クレジット → ⑦ハッシュタグ。リンクの中身は make_daily.py の `CONTACT_BLOCK` で変える。動画の「概要欄のリンクから」はこのブロックのこと。

### 2-4. 書くときの決まり
- **型のきまり（2026-11-21 オーナー指示）**：冒頭（`hook.say`）で「タートルアド」と名乗る行（例「タートルアドのタートルです。」）は、**自動で速さ 0.97** になります（「タートルアド」が早口に聞こえないように）。ほかの行は全体の `speed`（標準 1.15）のまま。変えたいときだけ、その行に `"speed"` を書く。`秒数表.md` に行ごとの速さが出ます。
- 決まったタイトルは `"title"` に書くと、`概要欄.txt` の先頭がそのタイトル1つ（＋ #Shorts）になります。案を複数出したいときは `"titles"`。
- 事実は出典に書いてあることだけ。「中小企業なら」は提案として言う。わからないことは言わない（`2026-11-20_第1回/ネタ一覧.md` の書き方と同じ）。
- 長さの目安：本編（宣伝カードの前まで）は「セリフの合計文字数 ÷ 約6.5文字/秒」。平日の本編30〜45秒なら本文セリフは**190〜280字**。そのあとに最後の部分（約12〜15秒）が自動で付く。あいさつ動画（greeting）は全体で45秒以内。チェックは本編の秒数で見る。
- ひな形の `【…】` が残っていると実行が止まります（書き忘れ防止）。


### 2-5. AI社員紹介（`"type": "staff"`・土曜。2026-11-21 オーナー決定）
見本：`資料/ai_video/daily/2026-11-28/台本.json`（1本目・デザイン主任）。ひな形：`台本ひな形/土曜_AI社員紹介.json`。

**進行**（型が自動で組む）
1. 冒頭：タートル「タートルアドのタートルです。今日は、仲間を紹介するよ！」（番組名「AI社員紹介」）
2. 本編：主役のAI社員が**下からぴょんと登場**（タートルは左下に小さくよける）。右に名札（役の名前・声の名前）。主役の声・口パク・まばたきは自動。

## 5-2. YouTubeへ出す（n8n が毎日12:00に自動で公開する。下の Webhook 版は予備）

> YouTube は n8n『AI動画編集部 YouTube毎朝自動投稿』(DgDoF4vapNLTByLb) が毎日12:00に自動で公開する。push は遅くとも12:00まで（Instagramのため8:20までが目標）（GitHub の `投稿情報.json` の `youtube` 欄を読み、`fact_checked=true` の日だけ公開）。下の Webhook 版は予備として残している。

**しくみ（2026-11-21 オーナー決定：最初から公開）**：毎朝のセッションが MP4・タイトル・概要欄を n8n の Webhook に送る → n8n が YouTube に**公開**でアップ → LINEでオーナーに「今日の動画を公開しました：タイトル／リンク」が届く（気になればYouTube Studioで非公開にできる）。
**ただし公開になるのは `fact_checked=1`（裏取り係の「確認済み」）を付けたときだけ。** 付けていないと限定公開に落ち、LINEで「事実の確認が終わっていないので限定公開で止めました」と届く。失敗したときも LINE で「どこで失敗したか」が届く。

**送る項目**（multipart/form-data）
| 項目 | 中身 |
|---|---|
| `video` | MP4ファイル（**15MBまで**にする。n8nの受け取り上限が16MBのため） |
| `video_url` | （`video` の代わり）GitHubに push 済みの動画の raw のURL（`https://raw.githubusercontent.com/sp734sn9boy-afk/turtlead-reels/<コミット>/…mp4` だけ受け付ける）。15MBを超えるときはこちら |
| `title` | タイトル（100文字まで。`<` `>` は使えない）。概要欄.txt の1行目 |
| `description` | 概要欄（概要欄.txt の3行目から最後まで。5000バイトまで） |
| `tags` | タグ（カンマ区切り。`#` は付けても外される） |
| `privacy` | `public`（公開・既定）／`unlisted`（限定公開）／`private`（非公開） |
| `fact_checked` | `1` = 裏取り係の確認済み。**これが無いと public でも限定公開に落ちる**。裏取り係の「確認済み」が出た回だけ付ける（あいさつ動画など事実確認の対象がない回は付けてよい） |
| `publish_at` | （任意）決めた時間に自動で公開するとき。例 `2026-11-22T07:00:00+09:00`（今から15分以上あと）。このときは「非公開＋予約公開」でアップされ、その時刻にYouTubeが公開する（`fact_checked=1` が必要） |
| `dry_run` | `1` にすると、チェックだけして結果を返す（YouTubeにも上げない・LINEも送らない）。最初の確認用 |

**合言葉（Webhookを守るヘッダー）**：値はリポジトリにも台本にも書かない。
- おすすめ：クラウド環境の「ネットワークの秘密（network secret）」に、ホスト `turtlead.app.n8n.cloud`・ヘッダー名（n8nで決めた名前。例 `X-Ai-Video-Key`）で保存してもらう。こうするとプロキシが自動で付けるので、コマンドに合言葉は出てこない。
- または環境変数 `AI_VIDEO_KEY`（値）と `AI_VIDEO_KEY_HEADER`（ヘッダー名）に入っていれば、下のコマンドがそれを使う。

**決まり**：毎日の台本には `"title"` を必ず書く（概要欄.txt の1行目が「タイトル1つ」になるように。案が複数のままだと送らない）。

```bash
cd /home/user/turtlead-reels
DAY=2026-11-22                                   # 今日の日付
DIR="資料/ai_video/daily/$DAY"
MP4="$DIR/turtle_ai_${DAY}_youtube.mp4"   # 2026-11-21 以前に作った日は turtle_ai_$DAY.mp4
URL="https://turtlead.app.n8n.cloud/webhook/ai-video-youtube-upload"

# 1) 送る前の確認（大きさ・タイトル）
SIZE=$(stat -c %s "$MP4"); echo "MP4: $SIZE バイト"
[ "$SIZE" -le 15000000 ] || { echo "15MBを超えています。送らずにリーダーへ報告"; exit 1; }
TITLE="$(head -n 1 "$DIR/概要欄.txt")"
case "$TITLE" in 【タイトル案*) echo "タイトルが決まっていません（台本に title を書く）"; exit 1;; esac
DESC="$(tail -n +3 "$DIR/概要欄.txt")"
TAGS="AI,生成AI,AIニュース,中小企業,タートルアド,AI動画編集部"

# 合言葉ヘッダー（環境変数があるときだけ付ける。ネットワークの秘密で自動で付く場合は不要）
AUTH=(); [ -n "${AI_VIDEO_KEY:-}" ] && AUTH=(-H "${AI_VIDEO_KEY_HEADER:-X-Ai-Video-Key}: $AI_VIDEO_KEY")

# 2) まずチェックだけ（dry_run=1：YouTubeには上がらない）
curl -sS -m 300 "${AUTH[@]}" \
  -F "video=@$MP4;type=video/mp4" \
  --form-string "title=$TITLE" --form-string "description=$DESC" \
  --form-string "tags=$TAGS" --form-string "privacy=public" --form-string "fact_checked=1" \
  --form-string "dry_run=1" \
  -w '\nHTTP %{http_code}\n' "$URL"
# → {"ok":true,"dry_run":true,...} と HTTP 200 ならOK

# 3) 本番（公開でアップ。HTTP 202 が返ればn8nが受け付けた。結果はLINEでオーナーに届く）
#    fact_checked=1 は、裏取り係の「確認済み」が出た回だけ付ける。無ければ限定公開に落ちる
curl -sS -m 600 "${AUTH[@]}" \
  -F "video=@$MP4;type=video/mp4" \
  --form-string "title=$TITLE" --form-string "description=$DESC" \
  --form-string "tags=$TAGS" --form-string "privacy=public" --form-string "fact_checked=1" \
  -w '\nHTTP %{http_code}\n' "$URL"
# 決めた時間に自動で公開に切り替えるときだけ、上に次の1行を足す：
#   --form-string "publish_at=${DAY}T07:00:00+09:00" \
```

**返ってくる答えの意味**
| 答え | 意味・やること |
|---|---|
| HTTP 202 `{"ok":true,"accepted":true}` | 受け付けた。アップの結果はLINEに届く。何度も送らない（同じ動画が2本上がる） |
| HTTP 200 `{"dry_run":true}` | チェックだけ成功（アップはしていない） |
| HTTP 400 `{"ok":false,"error":"…"}` | 中身の不備（errorに理由）。直して送り直す。LINEにも届く |
| HTTP 403 / 401 | 合言葉が違う・付いていない。リーダーへ報告（値をチャットに貼らない） |
| HTTP 404 | ワークフローが有効になっていない。リーダーへ報告 |
| HTTP 413 | 動画が大きすぎる（16MB超）。リーダーへ報告 |

## 5-3. Instagramへ出す（n8n が毎朝8:30に自動で投稿する。2026-11-21 有効化）

**しくみ（合言葉いらず）**：毎朝のセッションは、その日のフォルダに `投稿情報.json` を書いて、動画・キャプションと一緒に **push するだけ**。Webhook に送る作業はいらない。
n8n のワークフロー「AI動画編集部 Instagramリール自動投稿」（https://turtlead.app.n8n.cloud/workflow/jlzHH1gX8xozeZOg ・**有効**）が**毎朝8:30（日本時間）**に GitHub（ブランチ `claude/intelligent-fermat-uppvf6`）の `資料/ai_video/daily/<今日の日付>/投稿情報.json` を見に行き、次のように動く。

| 8:30 の時点の状態 | n8n がすること |
|---|---|
| `投稿情報.json` が無い | 投稿しない。LINEで「今日の動画がまだありません」（＝毎朝の作業が失敗した、または push が8:30に間に合わなかった合図） |
| 書き方の不備・動画やキャプションのファイルが無い | 投稿しない。LINEで理由を知らせる |
| `fact_checked` が `false` | 投稿しない（Instagramには限定公開がないため）。LINEで「確認済みがないので止めました」 |
| `fact_checked` が `true` で、同じファイル名がまだ投稿されていない | Instagram の **turtle_ad_pro** にリールで投稿（AIラベル「AI情報」つき）→ LINEで「リールを投稿しました：リンク」 |
| 同じファイル名がもう投稿済み | 2回目は投稿しない。LINEで「もう投稿済みなので止めました」 |

- 投稿先は turtle_ad_pro だけ。投稿は n8n の「Instagram投稿予定表」にも記録される（予定表の自動投稿の「1日2本まで・3時間あける」に数えられる）。
- キャプションのチェック：2200文字・ハッシュタグ30個まで。「VOICEVOX:猫使ビィ」と「AIチームが…作っています」が入っていないと不備で止まる（make_daily.py が作る `キャプション_instagram.txt` ならそのまま通る）。
- AIラベル：API の `is_ai_generated=true` で付ける。断られたときはラベルなしで投稿し、キャプションの一言で代える（LINEにその旨が出る）。
- **8:30 までに push を済ませる。** 間に合わなかった日は自動では出ない（LINEで知らせが届くので、リーダーが手で対応する）。

### 投稿情報.json の書き方（毎朝のセッションが必ず書く）
場所：`資料/ai_video/daily/<日付>/投稿情報.json`（動画・キャプションと同じフォルダ）。中身：
```json
{
  "date": "2026-11-22",
  "fact_checked": true,
  "instagram": {
    "video": "turtle_ai_2026-11-22_insta_tiktok.mp4",
    "caption_file": "キャプション_instagram.txt"
  },
  "youtube": {
    "video": "turtle_ai_2026-11-22_youtube.mp4",
    "description_file": "概要欄_youtube.txt",
    "enabled": true
  }
}
```
- `youtube` 欄：n8n「AI動画編集部 YouTube毎朝自動投稿」が12:00に読む。`video` はYouTube版の動画のファイル名、`description_file` の1行目がタイトル・3行目からが説明文。
| 項目 | 決まり |
|---|---|
| `date` | その日の日付（フォルダ名と同じ）。違うと不備で止まる |
| `fact_checked` | **ニュースの回は、裏取り係が「確認済み」を出したときだけ `true`**。確認が済んでいない・NGが出たときは `false`。AI社員紹介・あいさつなど、事実確認の対象がない回は `true` |
| `instagram.video` | Instagram版の動画の**ファイル名だけ**（フォルダ名は書かない）。ふつうは `turtle_ai_<日付>_insta_tiktok.mp4` |
| `instagram.caption_file` | キャプションの**ファイル名だけ**。省略すると `キャプション_instagram.txt` |

- JSON の形が崩れていると止まる。書いたら `python3 -m json.tool 資料/ai_video/daily/$DAY/投稿情報.json` で確かめる。
- 動画（mp4）・キャプション・投稿情報.json の3つを**同じコミットで push** する。push した後、次で届いているか確かめる（どれも 200 ならOK）：

```bash
cd /home/user/turtlead-reels
DAY=2026-11-22
BASE="https://raw.githubusercontent.com/sp734sn9boy-afk/turtlead-reels/refs/heads/claude/intelligent-fermat-uppvf6/%E8%B3%87%E6%96%99/ai_video/daily/$DAY"
for f in 投稿情報.json "turtle_ai_${DAY}_insta_tiktok.mp4" キャプション_instagram.txt; do
  ENC=$(python3 -c 'import sys,urllib.parse;print(urllib.parse.quote(sys.argv[1]))' "$f")
  echo "$(curl -s -o /dev/null -w '%{http_code}' -I "$BASE/$ENC") $f"
done
```

- あとから「やっぱり今日は出さない」ときは、8:30 より前に `fact_checked` を `false` にして push する。8:30 を過ぎて投稿済みのものは、Instagramアプリで非表示（アーカイブ）にする（オーナーの作業）。

### 予備：Webhook の入口（今は無効）
同じワークフローに Webhook（`/webhook/ai-video-instagram-reel`・合言葉ヘッダーつき）の入口もあるが、**ノードを無効にしてある**（合言葉の受け渡しが済んでいないため）。使うときはリーダーが n8n で有効に戻してから。項目は `video_url`（GitHub の raw のURL）または `video`（mp4・15MBまで）・`caption`・`fact_checked=1`・`ai_label`・`dry_run=1`。

## 6. よくあるつまずき
| 症状 | 原因と直し方 |
|---|---|
| `VOICEVOX につながりません` | エンジンが起動していない。1-2・1-3 をやり直す。`docker ps` で `vv` があるか確認。起動直後は10〜20秒待つ |
| `Cannot connect to the Docker daemon` | dockerd が止まっている。1-2 を実行 |

| 読み方がおかしい（例：十分→じゅっぷん、日本→にっぽん、英語名） | `秒数表.md` の「読み」を見て、そのセリフに `"read"` を書く。よく出る言葉は `readings` に追加 |
| `字幕がはみ出しそう` | `/` の位置を変えて2行に分ける。1行18字まで |
| `長さ ○秒は、この型の目安の外` | セリフを足す・削る（平日は30〜45秒） |
| `台本にひな形の【…】が残っています` | ひな形の【】を書きかえる |
| HyperFrames が `Chrome` / `browser` で失敗 | `node ~/.claude/skills/hyperframes/scripts/plugin-cli.mjs browser ensure` |

| 書き出しが遅い | 正常（GPUなしのソフト描画で長さの約3.2倍）。日曜90秒なら5分弱。ツールの時間切れが心配なら `run_in_background` で実行 |
| check の「注意」（YouTube Shortsの右端の安全範囲・小さい文字など） | 元の型（HyperFrames版）と同じ配置から出るもの。エラーではない。気になるときは check.json を見る |

| カードの文字が大きすぎ・小さすぎ | 文字の大きさは枠に合わせて自動で縮む。長すぎる文は短くするのが一番 |
